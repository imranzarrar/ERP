Design rationale

Grounded in how the category-leading POS platforms actually solve this — Toast, Square, Clover, and Lightspeed — plus published touch-target research, not invented from scratch. See sources at the bottom.

1. Two-tier catalog: a curated Favorites grid, backed by the full catalog

Every item in the product catalog can optionally be marked "Show on POS Grid" with a priority position — the same mechanism Square's Favorites Grid and Clover's per-category position field use. The grid only ever shows the top N priority items, where N is however many tiles currently fit. The other 10–14 items (of a 24-40 item catalog) aren't gone — they're one tap away via search (always visible, opens the OS on-screen keyboard — no physical keyboard assumed anywhere) or their own category tab.

2. Density is rows × columns, not a flat tile count — and tile size is computed, not fixed

Toast's own admin setting is literally "Menu Grid Dimensions: columns × rows," because a flat number ("30 boxes") doesn't answer how they're arranged on a given screen. The grid above uses CSS Grid with fractional (fr) sizing — the same screen space is divided into however many cells are configured, so a 12-tile shop gets noticeably larger, easier-to-hit buttons than a 30-tile one on identical hardware. Try the Compact vs. Dense presets above.

3. Ergonomic floors are enforced, not just allowed

Kiosk/POS touch-target research (NN/g, ISO guidance, accessibility studies) converges on roughly 12–20mm minimum per target — noticeably larger than phone or desktop UI minimums, because staff move fast, wear gloves, or work in bright light. A "tier-1" system doesn't just let an owner type in "12 columns × 10 rows" and ship broken tiles — it warns when the computed tile size would fall below a safe floor for the target screen (see the warning banner triggered by extreme Custom values).

4. Category tabs, color-coded, exactly like Clover and Lightspeed

Clover assigns each category a hex color and an explicit position (lower number = appears first); Lightspeed calls these "main screens" (up to 20) with drag-and-drop ordering. Here, every tile carries a colored top-edge matching its category tab, so a barista scans by color before they've even read the label — proven to cut mis-taps on busy screens.

5. Modifiers open a real step, not a cramped popover

Coffee items need Size / Milk / Extra Shot before they mean anything — these are "Option Sets" in Toast/Square/Clover terminology, attached per item, with required groups distinguished from optional ones. Tap "Latte" above to see it: a full-width modal with large chip buttons (not a dropdown — nothing here assumes a keyboard or a precise pointer), required groups blocking Add-to-Cart until chosen, optional groups skippable.

6. Curation is a tap-to-place workflow, not fragile drag-and-drop

Click "Arrange Grid" above. Rather than free-form dragging (finicky on a touch screen and in an embedded demo alike), the owner taps an item in the unassigned tray, then taps the grid slot to drop it in — same result as Square's "press and hold to rearrange," implemented in a way that also works cleanly with a finger, not just a mouse. A red × pulls any tile back off the grid instantly.

How this maps onto Warraq's own data model

  • Per-product fields (Product Catalog → Products & Pricing): posGridPosition (nullable integer — null means "not on the grid," a number is its priority slot) alongside the existing categoryId and POS-enabled flag already in the schema.
  • Per-company/terminal setting (Settings & Companies → POS Terminal Settings, where the image-size limits already live): posGridColumns / posGridRows, plus a preset selector (Compact/Standard/Dense/Custom) mirroring the demo above.
  • Modifier groups as a new lightweight construct attached to a product: an ordered list of option sets, each with a name, required/optional flag, and choices (each choice optionally carrying a price delta) — reusable across every drink that needs Size/Milk/Shots.
